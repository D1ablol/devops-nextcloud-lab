

# 1. Как перенести коммиты из одной ветки в другую?
## Для этого используется команда git cherry-pick (буквально: «сорвать вишенку»).

* Как это работает: Вместо того чтобы сливать всю ветку целиком, ты переходишь в ту ветку, куда хочешь перенести изменения, и пишешь команду с хэшем (номером) нужного коммита.

# Пример:

* Переключаешься в целевую ветку: git checkout main

* Переносишь конкретный коммит: git cherry-pick <хэш_коммита>

* Зачем нужно: Удобно, когда в другой ветке случайно сделал полезный фикс или написал нужную функцию, и ее нужно срочно забрать к себе, не таща весь остальной «мусор» из той ветки.

# 2. Что такое merge confict (конфликт слияния) и каковы причины?
## Что это такое: Ситуация, когда Git не может автоматически понять, какой вариант кода оставить, и останавливает процесс слияния (merge или pull), прося человека решить спор вручную.

## Основные причины:

* Два разработчика (или ты на разных ПК) изменили одну и ту же строчку в одном и том же файле по-разному.

* Кто-то удалил файл, а второй человек в этот же момент внес в него изменения.

* Как решать: Git помечает конфликт специальными строчками (<<<<<<<, =======, >>>>>>>). Ты открываешь файл, ручками выбираешь, какой вариант кода оставить (удаляя эти технические метки), делаешь git add и новый git commit.

# 3. Как работает git pull (что под капотом)?
## Команда git pull — это на самом деле две команды в одной. Когда ты ее пишешь, происходит следующее:

* git fetch (Забрать): Git обращается к удаленному репозиторию (например, на GitHub) и скачивает оттуда свежую историю и изменения к себе на компьютер, но не трогает твои текущие файлы в рабочей зоне.

* git merge (Объединить): Затем Git пытается автоматически соединить (смержить) скачанные изменения с твоей текущей локальной веткой.

* Простыми словами: git pull = «скачай то, что изменилось в интернете, и сразу натяни это на мой текущий проект».
